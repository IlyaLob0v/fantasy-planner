# Сервер синхронизации

Аккаунты и пересылка записей между устройствами «Штаба гильдии». Правил игры сервер не знает: запись хранится как JSON и сливается по времени правки. Устройство и протокол описаны в [specs/sync.md](../specs/sync.md).

## Тестовый сервер на своём компьютере (Windows)

1. Поставь [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запусти его.
2. Скачай репозиторий (зелёная кнопка **Code → Download ZIP** на GitHub) и распакуй.
3. Открой PowerShell в папке `server`, скопируй образец настроек и впиши в `.env` свой пароль базы (`POSTGRES_PASSWORD=...`):

   ```powershell
   copy .env.example .env
   notepad .env
   docker compose up -d --build
   ```

   Если тестовый сервер уже запускался раньше со встроенным паролем, впиши `POSTGRES_PASSWORD=guild` или сотри базу: `docker compose down -v`.

   Первая сборка идёт несколько минут. Проверка: в браузере открой <http://localhost:8080/health>, должно появиться `ok`.
4. Узнай адрес компьютера в Wi-Fi: `ipconfig`, строка **IPv4-адрес** (например, `192.168.1.23`). Телефон будет подключаться к `http://192.168.1.23:8080`.
5. Первый раз Windows спросит про доступ Docker к сети: разреши для **частных сетей**.

Остановить: `docker compose down`. Данные лежат в томе `guild-db` и переживают перезапуск. Стереть всё: `docker compose down -v`.

Пока компьютер выключен, приложение работает как обычно и копит изменения, а сверка пройдёт при следующем подключении.

Такой сервер говорит по HTTP без шифрования: годится только для домашней сети. Порт 8080 наружу (на роутере) не открывай.

## Сервер в интернете

Нужны VPS с Docker и домен, A-запись которого указывает на сервер.

1. В `.env` впиши `POSTGRES_PASSWORD` (длинный случайный) и `DOMAIN` (например, `guild.example.ru`).
2. Запусти:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
   ```

Снаружи открыты только порты 80 и 443 у [Caddy](https://caddyserver.com/): он сам получает сертификат Let's Encrypt и пересылает запросы серверу. База и сам сервер доступны только внутри сети Docker. В приложении адрес сервера: `https://guild.example.ru`.

Сервер узнаёт адрес клиента из `X-Forwarded-For` только с `TRUST_PROXY=1`, его ставит `docker-compose.prod.yml`. Без прокси эту переменную не включай: тогда адрес смог бы подделать любой.

## Разработка

Нужны Rust 1.94+ и Postgres 16.

```bash
export DATABASE_URL=postgres://postgres@localhost:5432/postgres
cargo clippy --all-targets -- -D warnings
cargo test      # каждый тест создаёт себе чистую базу
cargo run       # BIND_ADDR по умолчанию 0.0.0.0:8080
```

## API

| Запрос | Что делает |
|---|---|
| `POST /v1/auth/register` `{email, password, device_name}` | Новый аккаунт, ответ `{token, device_id}` |
| `POST /v1/auth/login` `{email, password, device_name}` | Вход нового устройства |
| `POST /v1/auth/logout` | Отзывает токен этого устройства |
| `POST /v1/auth/password` `{password, new_password}` | Смена пароля; все остальные устройства выходят |
| `DELETE /v1/account` `{password}` | Удаляет аккаунт и все записи |
| `POST /v1/sync/push` `{changes: [{table, uid, updated_at, data}]}` | До 1000 записей, ответ `{accepted}` |
| `GET /v1/sync/pull?after=N` | До 500 записей после курсора, ответ `{changes, cursor, more}` |

Токен передаётся в `Authorization: Bearer <токен>`, не больше 10 запросов в секунду. Сессия, которой не пользовались 90 дней, гаснет. Ошибки приходят как `{kind, message}`.

Лимиты паролей (вход, смена пароля, удаление аккаунта): 5 неудач с одного адреса по одному аккаунту дают паузу на минуту, 30 неудач с адреса за 15 минут или 50 неудач по аккаунту за час тоже ставят паузу. С одного адреса не больше 5 новых аккаунтов в час. На аккаунт до 200 000 записей. Одновременно идёт не больше 4 проверок пароля.
